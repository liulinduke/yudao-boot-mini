
# 发群帖发布完成检测修复计划

## 问题分析

根据用户反馈，发群帖任务实际发布成功但提示失败：

```
[发群帖] composer 已打开 
[发群帖] 内容已输入 
[发群帖] 已点击发布按钮 
[发群帖] ❌ 发布到 adssddc123 失败: 等待发布完成失败: Error: 发布超时 
```

**根本原因**：`WaitForGroupPublishComplete` 方法检测逻辑不完善：

1. 当前逻辑：检测是否存在带有 `[role="textbox"]` 的 `[role="dialog"]`
2. 问题：发布成功后可能出现其他弹窗（如成功提示、再次发帖的快捷框等），导致误判 composer 仍存在
3. 用户反馈"好像有两个"发帖框，说明可能发布成功后自动打开了新的发帖入口

## 修复方案

### 1. 增强 composer 识别逻辑
- 使用更精确的选择器识别真正的发帖 composer
- 添加多个判断条件（包含发布按钮、特定样式特征等）

### 2. 添加发布成功的多重验证
- 检测 URL 是否变化（发布成功后可能跳转到帖子页面）
- 检测页面是否显示发布成功提示
- 添加超时前的最后检查，避免误判

### 3. 添加详细调试日志
- 在检测过程中输出当前页面的 dialog 数量和特征
- 便于定位问题

## 修改文件

| 文件 | 行号 | 修改内容 |
|------|------|----------|
| `BrowserMatrixWindow.GroupPublishExtension.cs` | 418-438 | 修改 `WaitForGroupPublishComplete` 方法 |

## 具体修改

将现有的检测逻辑：
```csharp
const hasComposer = () => [...document.querySelectorAll('[role="dialog"]')]
    .some(d => d.querySelector('[role="textbox"]'));
```

改为更精确的检测：
- 检测 dialog 是否同时包含 textbox 和发布按钮
- 添加对页面成功状态的检测
- 添加详细日志输出

## 风险评估

- **低风险**：仅修改发布完成的检测逻辑，不影响发布流程本身
- **兼容性**：增强的检测逻辑向后兼容，不会影响正常发布流程
